## 读结果之前必须知道的四件事

1. **选择是 out-of-sample 的（新 backbone）。** 每个新 backbone 的 trunk 只在 pool 前 5 个 session 上训练，pool 第 6 个（最晚）session `pool[-1]` 不进 trunk；它是 P0 early stopping 的 session，也是 R1-stream / R2 / R3 规则的选择 session，trunk 没见过且早于该 backbone 的所有 target（因果）。原因：P3 §R.12 显示 in-sample（IS）选择会塌向 “不改动”。**例外**：复用的 `sm_0307`（现有 month trunk 看过全部 6 个 pool session）的选择只能是 IS（选择 session 20140306），rows 里 `selection_oos=false`。**sm_0307 的 rows 不得与 OOS 的 rows 合并，也不得与 P3 / drift-curve 的 R1–R3 rows 合并**（后者的规则在 20140307 上选，而 20140307 恰好是 sm_0307 的 target）。`analyze_expansion.py` 的所有分组键都含 `selection_oos`，并拒绝没有 `rule_version == expansion_v2` 的 rows。
2. **按 target session 聚类，不按 (backbone, target) 对。** 27 个 sub-C (backbone, target) 对只覆盖 **19 个不同的 session**：0713、0716 各被 3 个 backbone 评测；0629、0706、0709、0714 各被 2 个；sm_0611 的 target 0616 / 0617 是 P1 的设计 target（旧 days 池的 dev target，这里是不同 pool）。同一 session 在不同 backbone 下的 rows 不是独立证据，所以：先在每个 (subject, stratum, selection scope, B, 对比) 内对同一 session 的各 backbone 取均值，再对 session 做 bootstrap（10,000 次，seed 0）和 t 区间；`n_sessions` 与 `n_backbone_target_pairs` 同时报告。只有 1 个 session 的组（如 sm_0307）不报告 CI。**backbone 层面的离散**（各 backbone 均值的 min / max / sd，以及同一 session 跨 backbone 的最大差）单独列在 `backbone_spread.csv`。
3. **days 标签 ≠ trunk 的 gap。** stratum 与 `gap_days` 从 pool[-1] 起算；新 trunk 的最后训练 session 比 pool[-1] 更早，所以 `trunk_gap_days >= gap_days`（例如 sm_0627 的 target 20140627：到 pool[-1]=20140626 为 1 天，到 trunk 最后训练 session 20140307 为 112 天）。`paired_session_cluster_by_trunk_gap.csv` 按 trunk gap 重新分层。
4. **披露（不是禁止）：** 部分 sub-C session 在其他 SPINT / btransform 协议里是 exam / test face——`EXP1_NARROW_EXAM_SESSIONS` = 0713、0714、0715、0716（`plan.py:682`，exp1_narrow / exp1_poverty 的 exam face）；APST development session 1103、1104、1106、1109、1110、1112（= exp2_full / exp2015_full 的 exam face，即 manifest 的 val）。`EXP2016_EXAM_SESSIONS`（`plan.py:727`）里的 2016 session 本扩展**不使用**。这些 face 在不同协议里是各自独立的测量，本扩展的 rows 不能与那些协议的 face 数字直接比较。final（APST test）session 没有被使用，loader 对它们抛 `PermissionError`。
