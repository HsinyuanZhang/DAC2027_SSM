## 2. 统计口径

* 先对每个 (backbone, target, B, latency, method) 在 seed 上取均值（p_prior / ridge_cca 无 seed）；再按 tier 把同一个 target session 在不同 backbone 下的值取均值（例如 20150713 在 `sc_0708` 与 `sc_0713` 下都在 ≤30 d，合成 1 个 session；20150709 / 0713 / 0716 同时出现在 ≤30 d 与 31–180 d，两层各算一次）；最后对 session 做 10,000 次 percentile bootstrap（seed 0）。“B4-33”先对每个 session 的 B ∈ {4,8,16,33} 取均值。
* 差都是配对差（同一 (backbone, target, B) 上的 方法 − P0），不可用的格子不进均值也不被填补；括号里 `k/n` 是差为正的 session 数 / session 数。**COMBO 的 B4-33 只包含可用的 B**（B=33 在 17 个 (a) target 上没有规则），所以它的 B4-33 与其他方法的 B4-33 覆盖的 B 不同，请优先看按 B 的列。
* **IS backbone `sm_0307`（target 20140307）不进任何 tier**：它的 selection session 是 trunk 训练 session（IS），且 20140307 本身是旧规则的 selection session，不应作为 target 报告。它的 1 行在 T7 单独给出，没有 CI。20140307 作为**别的 target 的 selection session**（legacy episode，早于那些 target）出现在 pool 里（T8 的 session 列表），这是协议允许的。
* 每个 tier 只有 7~17 个 session，CI 宽；多个 pair 共用同一个 target session 的信息已在聚类里合并（T1：≤30 d 有 10 个 pair 但 8 个 session）。

* latency 1（sensitivity）：B4-33 的差与 latency 0 几乎相同（W_alpha (a)：0.004 / 0.031 / 0.178 对 0.004 / 0.031 / 0.178；R2 参考在 ≤30 d 由 +0.0124 降到 +0.0108，在 31–180 d 由 +0.0498 降到 +0.0481）。表在 T3.1 / T4.1 / T5.1。

## 5. 数据问题与限制

* 所有 tier 的 session 数少（7~17），且 >180 d 的 7 个 pair 里 6 个来自同一个 backbone `sc_0309`（trunk 未收敛），另 1 个来自 `sm_0512`（同样未收敛）；这一层的结论主要是 `sc_0309` 的结论。
* sub-M 的 7 个 pair（sm_0611 ×5、sm_0627、sm_0512，分布在三个 tier）与 sub-C 混在 tier 内；tier 之间的比较因此也混了 subject 与 backbone 的差异，per-backbone 表（T6.*）给出每个 backbone 自己的数字。
* (b) 协议下 selection session 只有 1 个，S1-causal (b) 在所有 B 都退回 P0，COMBO (b) 不可用；这是 strict 协议在新 backbone 上的结构后果，不是 bug（`pool_complete` 全 True）。
* 若干 (a) 规则（W_alpha、COMBO、CCA+S1）与 R2 / R3 的 source 规则不是同一份选择，因此 R2 / R3 只作参考，不与 causal 规则合并成排名。

## 6. 运行中遇到的问题

* **`margin_pick` 在混合 grid 的 episode 上抛 `StopIteration`**（首次 `causal-eval` 立刻失败）。原因：legacy S1 episode 的 `rebase` grid 有 45 个 (η, ρ) 点（没有 η=0），本地 `causal-source` 写的有 50 个点（含 η=0），而 `margin_pick` 用 `episodes[0]` 的点作为键。修复：键取所有 episode 的交集（η=0 相对自己的 base 增益为 0，从不 viable，所以不改变任何选择；所有 episode 同 grid 时行为不变）。已在 `tests/test_expansion_causal.py` 加测试并在主机上用 700 组 (target, B, η) 做了 `target_rules` 干跑；VM 上替换了 `ssm_decode/causal_protocol.py` 后重启 2b（stage 幂等，已写入的 sm_0307 行被保留）。
* 无其他失败；`colab exec` 偶发 `Connection was lost`，后台 job 未受影响。
