审核范围：提交 `f971b07..2c62872`（阶段 0′ 修复、时间前向评测框架、阶段 1′ 容量/K/配方消融、阶段 2′ 000688 上的 Track A 与 Track E），以及三份阶段文档。依据有三类：后台代码审查（15 项）、我对结果文件和 manifest 的直接核查、以及与仓库内 APST/LSTM 参考结果的对照。

## 0. 结论先行

1. **阶段 2′ 的两个门槛判定（4.2.5、4.7.6）都不成立，应改为“未定”。**
   - Track E 的 set 骨架在 source 上就没有训练起来：source 验证 R² 为 0.110，同一批数据上 AP 骨架为 0.611；训练 loss 一直大于 1，也就是比预测均值还差。
   - Track E 在 target 端的评测用错了单位：归一化单位的预测直接和原始单位的速度比较，所以报告的约 0.01 不是有效数字。
   - Track A 用的 AP 骨架没有按协议重训：延长预算的脚本复用同一目录，跳过了训练；best_step 仍等于预算上限 2000，结果与 10-04 的未收敛 run 逐位相同。
   - 000688 上取 K=12 超过了 FA 的可识别上限（Ledermann bound）。17 个 unit 时 K 最多约 11，15 个 unit 时最多约 10，所以闭式 FA 方法的解不唯一。
2. **仓库内的同协议参考说明，集合编码这个思路是可行的。** APST 在 sub-M 上用同样 6 个训练 session：只用活动 0.578，加 profile **0.808**，打乱 profile 0.031。这些是 final split 的结果，target 端不做梯度更新。作为对照，LSTM 用 32 个 trial 梯度微调为 0.703。我们 ui_grad 用 33 个 trial 在 dev split 上为 0.639。split 不同，不能直接比较，但足以说明 Track E 的失败出在实现和训练配方上，而不是思路。
3. **阶段 0′ 和 1′ 的主要结论成立**，有两处需要收紧措辞：
   - 128 KB 预算内的配置（wide_n16 状态 103.9 KB、deep_n16 状态 77.9 KB）能达到超预算 wide 模型的多 target 水平。
   - N=16 是融合 kernel 允许的下限。
   - 漂移增强贡献约 +0.10，是目前测到的最大单项。
   - source 池的大小是一阶因素；单个 target 无法给方法排序。
   - 需要收紧的地方：“wide_n16 超过 wide”只差 0.005，落在 seed 波动之内，应写作“持平”；每个容量配置只有 1 个 source seed。
4. **现有测试没有拦住任何一个关键问题**（相关测试 34 项全部通过）。下一轮需要先加四个端到端检查：物理单位、source 拟合门槛、预算延长的实际执行、真正的置换检验。

## 4. 对下一轮迭代的启发

### 4.1 Track E：先复现 APST 的量级，再谈存内计算形态

同协议下 APST 能做到，我们的 E1 做不到，差别集中在四处：

| 方面 | APST | 我们的 E1 |
|---|---|---|
| profile 描述 | 33 个 trial 运动窗口的余弦调谐（T4），噪声低 | 每个 episode 只用 8 个 trial、带滞后的行为特征回归，噪声高 |
| 活动描述 | 学习得到的 activity identity 编码器（E0），输入 33 个 trial | 只有对数平均发放率和对数标准差两个数 |
| unit token | 每个 unit 的局部活动特征经 MLP 后做 slot 注意力（key 随活动变化） | 静态 key，直接折叠成线性表 |
| 训练 | 多阶段、长时间训练 | trunk 和读入都从随机初始化开始，2000 步，增强很强 |

建议的顺序：
1. 修好 A1、A2、A6、B1、B2、B5。
2. **source 拟合门槛**：set 骨架的 source 验证要达到 AP 骨架的水平（相差不超过 0.05），才能进入 target 评测。
3. **先接近 APST，再追求可折叠**：
   - 用 33 个 trial 的 T4 和一个 E0 式活动编码器作为描述；
   - trunk 从已收敛的 AP 骨架初始化，或先用 6 个 source session 的读入表做蒸馏，再联合训练。
4. 能复现到 APST 量级之后，再逐步换成可折叠的 E1/E2，量化“可折叠”付出的精度代价。真正的逐步动态 key（E4）也要实现出来，作为可信的上限。
5. 为了公平对照，**在 dev target（0616、0617）上运行 APST 的现有 checkpoint**，得到同一 split 下的参考数字，而不是拿 final split 的数字来比。

### 4.2 Track A：先满足可识别性和收敛

1. 000688 上取 K ≤ 10（由 source 池最少的 15 个 unit 决定），或者改用不受 Ledermann 上限约束的概率 PCA 或 PCA 读入。
2. 修复 A3，按规则重训 AP 骨架，直到 best_step 不再落在预算的最后 20%。
3. 测试“先验加梯度”的组合：ui_grad 从 E1 折叠表或 prior 表初始化（阶段 2′ 文档已提出）。如果这样能在 4–8 个 trial 上接近 33 个 trial 的结果，就是标签效率上的实际收益。

### 4.3 容量与状态：采用预算内配置，并补上 source seed

1. 默认使用 wide_n16，低状态的备选是 deep_n16。每个配置至少补 2 个 source seed，才能区分 0.01 量级的差异。
2. N=16 只是当前融合 kernel 的下限。硬件上如果需要更小的状态，用 PyTorch 参考扫描做精度评估，不受这个限制。

### 4.4 漂移增强是目前最大的单项，值得单独作为研究方向

1. 拆开 gain、offset、通道 dropout 各自的贡献，并扫描强度。
2. 用实测的 session 间漂移统计来设定增强的分布：例如逐通道标准差比在 0.4–2.0 之间（见 10-03 审核）。
3. 同一套增强也可以模拟存内阵列的器件漂移（列增益、整体增益），这把“对神经漂移鲁棒”和“对器件漂移鲁棒”放进了同一种训练机制，可以和路线图 D6 的联合漂移实验合并。

### 4.5 评测协议

1. source 池大小与时间间隔目前混在一起，需要按池大小分层报告；也可以用固定大小的滑动池（例如最近的 2 个 session）把两者分开。
2. M2 上只有 2020-10-28-Run1 拥有完整的 6-session 池，能与历史结果直接比较。

### 4.6 工程

1. 新增四个端到端检查，接入每个评测入口：
   - **物理单位**：断言预测与真值的尺度一致，例如两者标准差之比在合理范围内；
   - **source 拟合门槛**：source 验证低于阈值时，拒绝进入 target 评测；
   - **预算延长的实际执行**：读取 manifest，确认 steps 等于最终预算、best_step 不在最后 20%；
   - **真正的置换检验**：打乱描述行，重新折叠，再解码。
2. 延长预算时，每次尝试写入独立目录（沿用 `run_forward_eval.py` 的 `_x2`/`_x4` 做法）。
3. 两条工作线按模块划分归属，避免同时修改受保护的文件。
