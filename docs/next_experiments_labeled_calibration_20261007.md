# 下一轮实验指导：冻结骨架 + 少量标签 trial + 固定权重前向校准（2026-10-07，第二次修订）

本文件指导下一轮实验，优先级高于此前各路线文档中与之冲突的条目。执行 agent 必须按 §6 的队列**完整执行到底**，停止规则见 §7。

**目标：骨架完全冻结；只用 target session 的少量有标签 trial；适配的计算尽可能由固定权重的乘加完成（网络存放在 RRAM 中，在 source 上训练后冻结），前向算出每个 unit 的身份 embedding，以此完成跨 session 校准。**

> 修订记录：
> - 初版把“适合存内计算”落在推理时的乘加数量上，并把依赖梯度的方法列为主要候选。
> - 第一次修订改为“固定权重身份编码器”，但标签只以手工统计量（协方差、调谐曲线）的形式进入。
> - 本版加入三种依赖学习、先验更弱的标签用法（F6–F8），并把“误差驱动的前向更新”（F7）列为主要候选。

## 0. 主路线约束（不可偏离）

1. **骨架不微调。** trunk、W_lift、各层投影和 FFN 冻结，target 端不写 RRAM。trunk 的 LoRA、逐步解冻和 full FT 只作为参照行。
2. **只用少量有标签 trial。** 标签预算 B ∈ {1, 2, 4, 8, 16}，B=33 作上限参照。校准只用这 B 个 trial 的神经数据和标签。纯无标签方法只作参照行。
3. **target 端的适配只允许三类操作：**
   - (a) 在 B 个有标签 trial 上做流式累加；
   - (b) 固定权重网络的前向，包括冻结的 trunk 本身的前向，以及在 source 上训练后冻结的编码器、反馈矩阵；
   - (c) 把结果写入 SRAM（读入表、行增益与行偏置、输出仿射）。

   不允许：target 端的梯度和反向传播；以 target 数据为目标的迭代优化。F7 的“展开步”是事先固定的计算图（步数、步长、反馈矩阵都在 source 上学好），不是迭代优化。只允许很小的闭式统计构造，例如 3×3 的最小二乘、D×D 的输出 ridge。

   source 端训练编码器时可以使用反向传播，这属于预训练。
4. **推理形态不变**：校准结果折叠成静态读入表加行参数，推理时只多一次线性读入，再接冻结的 trunk。
5. **不在本轮范围内**：trunk 微调；把无标签校准作为候选；新的骨架家族；Track E 原有的 E1 在 M2 上的迭代；把 APST 当作优化目标。

## 1. 现有证据

1. 固定权重编码器这条路走得通：
   - co-adapted 的 E1b 在 000688 上不用标签、不做 target 梯度，达到 0.673；
   - APST 的 E0（固定权重编码器）加 T4（闭式）在同协议的 final split 上达到 0.808。
2. 标签目前几乎没有起作用：e1_profile（33 个 trial）0.690，e1_rate 0.673。
3. 在 M2 上，平均 source 表（不用标签）为 0.265–0.293，必须以它为先验做残差修正。
4. 纯回归式蒸馏不能跨 session 泛化（留一 session 检验只有 0.029），必须用 decode loss 做 episodic 训练。
5. **标签中可用信息的上限参照（依赖梯度）**：ui_prior 在 8 个 trial 时，三个时间间隔层分别为 0.536、0.500、0.397。
6. **理论依据**：读入表第 i 列的梯度等于 Σₜ Jₜᵀ rₜ x_{i,t}（rₜ 为残差，Jₜ 为穿过 trunk 的雅可比）。其中只有 Jₜᵀ 需要反向传播，残差与活动的交叉协方差只需前向和累加。F7 用一个学好的固定矩阵 G 代替 Jₜᵀ（feedback alignment 的思路）。

## 2. 判据

| 编号 | 判据 | 要求 |
|---|---|---|
| H1 | trunk 与 RRAM 参数不变（校准前后比对参数哈希） | 必须满足 |
| H2 | target 端反向传播次数 = 0；没有以 target 数据为目标的迭代优化 | 必须满足 |
| H3 | 适配运算中固定权重乘加所占的比例：固定权重前向（trunk 前向、编码器、G）的乘加数，除以适配的全部运算数 | 每一行都记录，越高越好 |
| H4 | 只使用 B 个有标签 trial 及其神经数据 | 必须满足 |
| H5 | 校准结果是静态边界参数，总量 ≤ 32 KB；推理时额外代价不超过一次线性读入 | 必须满足 |

APST 作对照：适配过程满足 H2，H3 较高；推理时每步要做逐 unit 的 token MLP 和注意力，不满足 H5。

## 3. 方法

### 3.1 共用部分

- **先验 T₀**：
  - M2 用冻结的直接模型 wide_n16，读入表即根层 `in_proj`；先验为 source 有效映射的均值（即 none 对应的映射）；
  - 000688 用 K=10 的 AP 骨架，先验为 profile 先验表；
  - 行增益 g₀ = 1，行偏置 o₀ = 0。
- **输出形式**：
  - 残差形式：T = T₀ + ΔT，M2 必须用；
  - 绝对形式：直接输出 T 的各列，000688 上与残差形式对比。
- **source 端 episodic 训练**（所有变体通用）：
  1. 每一步随机抽一个 source session s，随机取标签预算 B ∈ {1…16} 和 B 个 trial 作为校准数据；
  2. session s 的先验 T₀ 用**其他** source session 读入表的均值构造（留一），不能包含 s 自己的表；
  3. 按变体生成 T，在 s 的**其他** trial 上计算 decode loss（trunk 冻结），只更新校准网络；
  4. 增强：unit 子采样（在池化或 softmax 内部丢弃）、逐通道 gain 扰动、统计量噪声；把 B 作为输入；
  5. 训练遵守收敛规则：best_step 落在最后 20% 时延长预算，上限 4 次翻倍；每个配置训练 2 个 seed。
- **超参数选择**：在 source 的验证 session 上进行，不使用 target 的 query。

### 3.2 变体总表

| 编号 | 标签的用法 | 先验强度 | 角色 |
|---|---|---|---|
| F1 | 不用标签，只用活动统计（绝对形式） | — | 参照：不用标签能做到多少 |
| F2 | 手工标签统计，绝对形式 | 强 | 基线 |
| F3 | 手工标签统计，残差形式 | 强 | 基线 |
| F4 | 在最好的变体上加校准时的集合注意力 | — | 消融 |
| F5 | 逐项去掉 F3 的某类手工统计 | — | 消融 |
| F6 | 学到的统计量：φ(活动, 行为) 求和 | 中 | 主要候选之一 |
| **F7** | **误差驱动的前向更新：残差 ⊗ 活动，经固定的 G 映射** | **弱，有梯度作理论依据** | **主要候选** |
| F8 | 校准时 in-context 注意力，直接读入有标签序列 | 最弱 | 仅在 000688 上探索 |

### 3.3 F2/F3：手工统计量

对每个 unit i，在 B 个有标签 trial 上累加：
- 活动统计：发放率均值、方差，滞后 1/2/5 个 bin 的自相关，与先验读入得到的群体潜变量的相关；
- 标签统计：与行为在滞后 −2…+2 个 bin 上的交叉协方差（D×5）；CO 任务按 8 个目标方向分组的平均发放率；T4 式余弦系数；
- 有标签 bin 的数量。

编码器：MLP（宽度 64，2 层），输出 Δtᵢ（残差形式）或 tᵢ（绝对形式），以及 gᵢ、oᵢ。

### 3.4 F6：学到的统计量

- 对每个 unit i 和每个有标签 bin t，构造输入 [x_{i,t−4…t}，y_{t−2…t+2}，z₀,ₜ]。其中 z₀,ₜ 是先验读入给出的潜变量，可选。
- 固定权重特征网络 φ（MLP，宽度 64，2 层，输出 64 维），在所有有标签 bin 上取平均：mᵢ = meanₜ φ(·)。
- 再经固定权重网络 ρ（MLP，宽度 64）输出 Δtᵢ、gᵢ、oᵢ。
- 同一个 φ 被所有 unit、所有 bin 共享复用，H3 应当很高。

### 3.5 F7：误差驱动的前向更新（主要候选）

target 端的计算（以下全部是固定的计算图）：

1. 初始化：T⁽⁰⁾ = T₀（或 F3 的输出，见混合变体 F7+F3），g⁽⁰⁾ = 1，o⁽⁰⁾ = 0。
2. 对 s = 0, …, S−1：
   1. 用 T⁽ˢ⁾ 和冻结的 trunk，在有标签 trial 上做一次前向，得到 ŷₜ⁽ˢ⁾；
   2. 计算残差 rₜ⁽ˢ⁾ = yₜ − ŷₜ⁽ˢ⁾（用 source 的标签统计量归一化），取滞后窗口 r̃ₜ = [r_{t−L}, …, r_{t+L}]，维度 D(2L+1)。校准数据是事后完整记录的，可以使用未来的标签；
   3. 对每个 unit 累加：Mᵢ⁽ˢ⁾ = meanₜ r̃ₜ⁽ˢ⁾·x_{i,t}，同时累加活动能量 qᵢ = meanₜ x_{i,t}²；
   4. 修正：Δtᵢ⁽ˢ⁾ = η_s · G_s · Mᵢ⁽ˢ⁾ / (qᵢ + ε)。线性版本中 G_s 为 K×D(2L+1) 的固定矩阵；MLP 版本中，把 G_s 换成以 [Mᵢ, qᵢ, B] 为输入的小 MLP；
   5. 更新：T⁽ˢ⁺¹⁾ = T⁽ˢ⁾ + ΔT⁽ˢ⁾。
3. 输出 T⁽ˢ⁾ 写入 SRAM。

source 端训练：把 S 步展开成一张计算图，以“s 的其他 trial 上的 decode loss”为目标，学习 G_s 和 η_s。只在这里使用反向传播。

配置空间：
- S ∈ {1, 2, 3}；
- G 取线性或 MLP；
- L ∈ {0, 2}；
- G_s 在各步之间共享，或每步独立。

必须做的正确性测试：在合成的线性 trunk 上，令 G = Jᵀ、η 取学习率时，F7 一步的结果应与一次梯度下降逐元素相同。

### 3.6 F8：校准时的 in-context 注意力（仅 000688）

- 每个 unit 的输入序列：有标签 bin 上的 (x_{i,t}, yₜ, z₀,ₜ)，按时间均匀抽取，最多 512 个 bin。
- 固定权重的小 transformer（2 层，宽度 64，4 个 head）加一个汇总 token，输出 Δtᵢ、gᵢ、oᵢ。
- 只在校准时运行一次，推理时仍是折叠后的静态表。

### 3.7 参照行（不是候选）

1. source-only 先验（B=0）。
2. 闭式最小基线：行归一化加输出 ridge；prior_correct。
3. 依赖梯度的上限参照：ui_prior（3 个 seed）；M2 上 trunk 的 LoRA（量化“放弃微调”的代价）。
4. 无标签参照：EMA；co-adapted E1b 的 e1_rate（000688）；F1。
5. APST：只作背景。

## 4. 数据与记录

1. **D1：000688 sub-M**，三个时间间隔层：days（约 1 周）、month（约 3.7 个月）、year（约 15 个月）；K=10 的 AP 骨架。month 和 year 层的骨架先延长到满足收敛规则；仍不收敛的，在每一行标注。
2. **D2：M2**，时间前向的 5 个 target，冻结的 wide_n16。先用 source seed 0 跑完全部变体，再用 seed 1、2 复跑最终入选的变体。
3. 不使用 final session，不读取 `results/official_evalai/`。
4. 每一行记录：query R²（物理单位）；H1–H5；H3 中的各项乘加数；校准参数的字节数；单位比值；骨架与校准网络的收敛状态；seed。
5. 汇总：按 D1 的三层和 D2 分别给出 B=1…16 的标签效率曲线；逐 target 配对差值，对照对象为 ui_prior、source-only 先验和 F1。

## 5. 判定门槛

| 编号 | 门槛 | 通过后的结论 |
|---|---|---|
| G1 | B=8 时，某个固定权重变体在 D1 三层中至少两层不低于 ui_prior 减 0.03 | 固定权重前向可以替代梯度校准 |
| G2 | 在 D2 上，某个残差形式变体在 B ≥ 4 时高于 source-only 先验，且高出噪声底以上 | 在固定通道数据上，标签加固定权重前向带来实际增益 |
| G3 | 同一结构下，带标签的版本高于 F1，且高出噪声底以上，在多数层和多数预算上成立 | 校准确实在使用标签 |
| G4 | F7 与 ui_prior 的差距，相比 F3 与 ui_prior 的差距缩小一半以上 | 误差驱动的前向更新比手工统计更接近梯度 |
| G5 | 每个候选的每一行都满足 H1、H2、H4、H5，并记录 H3 | 不满足的不能列为候选 |

门槛未通过是一个实验结论，不是停止的理由（见 §7）。

## 7. 停止与继续规则（必须遵守）

1. **方法表现差、门槛未通过，都是结果，不是停止的理由。** 记录下来，继续下一项。
2. **报错或缺陷**：如果属于本轮范围，最多花约 1 小时修复，然后重跑受影响的部分。修不好的，在结果文档中写明阻塞原因和证据，跳过这一项（以及依赖它的项），继续后面的队列。
3. **不收敛**：按收敛规则延长预算到上限；仍不收敛的，在行里标注后继续，不要停下来等待。
4. **单项耗时超出预期**：缩小配置（减少 seed 或配置数），在文档中注明，然后继续。
5. **发现违反 H1、H2 或 H4 的情况**：修复之后重跑受影响的项，不要因此停止整个队列。
6. **只有以下情况可以停止：**
   - (a) Q0–Q12 全部完成，汇总文档已写完；
   - (b) 出现影响所有队列项的硬性阻塞，例如数据不可用、两张 GPU 都无法使用。此时写一份阻塞报告，说明已完成的部分和下一步需要什么，再停止。
7. 队列执行期间不要另起新方向。新想法写进结果文档的“后续想法”一节，本轮不执行。
